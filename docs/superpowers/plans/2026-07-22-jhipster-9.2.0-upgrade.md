# JHipster 9.2.0 Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade the MiniBlog backend from JHipster 9.1.0 to exactly JHipster 9.2.0 with the supported automatic upgrade workflow while retaining custom behavior.

**Architecture:** Invoke the exact JHipster 9.2.0 upgrade generator through `npx` so the stale local 9.0.0 installation cannot be selected. Let JHipster maintain its dedicated upgrade branch and merge history, reconcile any overlaps with project-specific security code, then validate metadata and the complete backend CI suite.

**Tech Stack:** JHipster 9.2.0, Java 21, Spring Boot 4, Maven Wrapper, Node.js 24, npm, Git, PostgreSQL configuration

## Global Constraints

- The target generator version is exactly `9.2.0`.
- Use JHipster's automatic upgrade sub-generator before any manual regeneration.
- Preserve the custom password encoding and DTO serialization protections.
- Keep entity definitions and application behavior unchanged except for intentional JHipster 9.2.0 generated changes and hardening.
- Do not use `--skip-checks` on the initial automatic-upgrade attempt.
- Allow the standard `jhipster_upgrade` commits and merge into `master`.
- Do not introduce unrelated refactoring or features.
